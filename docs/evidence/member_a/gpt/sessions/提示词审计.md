1. 先概括需求或提示词要解决的问题、目标读者、输入和期望输出；不清楚的地方标为歧义，不擅自补成确定事实。

3. 尝试构造反例、反向情形或最小失败案例，检查提示词是否会导致错误答案、过度自信、答非所问或互相冲突的行为。
4. 区分确定的逻辑缺陷、合理但未经支持的假设、表达歧义和单纯的风格偏好。没有证据时，不把意见包装成事实；没有实质缺陷时，明确说明审计未发现重大问题。

1. 保留已经确认的促销资格、活动适用商品集合和整单择优规则。本次裁决替换旧的行级分摊权重或尾差规则，不保留冲突的旧口径并行适用。
2. 先按现有已确认促销规则计算候选活动的整单应付和整单优惠，再进行行级分摊。不得先逐行独立舍入后将尾差全部放到末行。
3. 分摊权重统一为本次活动适用的各销售行优惠前小计，即该行参与活动的数量乘以优惠前成交单价。未参与活动的行分摊优惠为零。
4. 整单优惠以整数分表示。行级分摊使用精确整数分和整数余数计算，不在分摊中途先舍入到四位小数或其他精度。
5. 对当前仍未封顶的适用行，以其原始权重按比例分配剩余优惠分：
   - 对每行计算 `剩余优惠分 × 行权重` 除以当前未封顶行权重总和；
   - 用整数除法取得该行的基础分，余数保留为精确整数余数；
   - 余数更大的行优先取得尾分；
   - 余数相同的行按不可变、稳定的销售行 ID 升序决胜。
6. 逐行封顶：单行优惠不得超过该行可优惠金额，单行实付不得小于零。
7. 封顶后的再分配按以下方式执行：
   - 封顶行退出当前分摊集合；
   - 对剩余优惠分，在尚未封顶的适用行中按其原始权重重新归一化；
   - 按整数除法重新计算基础分和精确余数，再按余数降序、稳定 ID 升序分配尾分；
   - 若尾分分配使某行达到封顶，该行退出后，对仍未分完的优惠分重复以上过程；
   - 若可分配容量耗尽但优惠仍未分完，拒绝该次优惠计算，不得生成负优惠或负实付。
8. 优惠计算中，整单候选金额的舍入继续遵循 Spec 中现有、已确认的整单金额规则；将最终整单优惠统一到整数分后，再执行上述精确分摊。分摊算法自身不得使用中途小数舍入。
9. 验证所有适用行的行级优惠之和等于整单优惠，所有行实付之和等于整单应付。不得更改已经确认的促销资格或其他促销规则。

更新或新增验收场景，至少覆盖：

- 多个一分钱商品行分摊满减，不产生负优惠或负实付；
- 余数相同的行按稳定销售行 ID 升序分配尾分；
- 某行达到优惠封顶后，剩余优惠按未封顶行原权重重新分配；
- 行级优惠、整单优惠和实付金额总和守恒；
- 总优惠超过所有适用行容量时拒绝计算，且不生成部分销售记录；

2. 检查所有会改变库存的后续有效业务，包括销售出库、补货或位置转移、报损、库存调整及其他库存变更。后续新增的收货也计为后续有效库存变更。
3. 同一条码在任一库存位置存在后续有效库存变更时，拒绝冲销原单。不尝试判断后续变动是否实际消耗了原单数量，也不以净余额足够为由绕过阻断。

6. 后续业务只有在其原库存流水与配对反向流水均已完整冲销时，才作为一项完整撤销业务排除于有效后续活动之外。必须依据流水关联和完整冲销状态判断，不能只因净额为零就认定没有发生过后续业务。
7. 后续业务只完成部分冲销时，仍视为存在有效后续库存变更并阻止原单冲销。
8. 对原流水和反向流水按同一已撤销业务配对判断；完整冲销后不得将反向流水再次当成独立的有效后续业务。
9. 即使不存在后续有效库存变更，冲销仍须检查结果不会造成负库存。
10. 原单成功冲销时，保留冲销原因、原单关联和反向库存流水；同一原单不得重复冲销。

## 二、Q1：统一整单优惠的行级分摊算法

更新 Spec、PRD、ERD、数据字典和验收场景，使优惠计算只有一种解释：

1. 保留已经确认的促销资格、活动适用商品集合和整单择优规则。本次裁决替换旧的行级分摊权重或尾差规则，不保留冲突的旧口径并行适用。
2. 先按现有已确认促销规则计算候选活动的整单应付和整单优惠，再进行行级分摊。不得先逐行独立舍入后将尾差全部放到末行。
3. 分摊权重统一为本次活动适用的各销售行优惠前小计，即该行参与活动的数量乘以优惠前成交单价。未参与活动的行分摊优惠为零。
4. 整单优惠以整数分表示。行级分摊使用精确整数分和整数余数计算，不在分摊中途先舍入到四位小数或其他精度。
5. 对当前仍未封顶的适用行，以其原始权重按比例分配剩余优惠分：
   - 对每行计算 `剩余优惠分 × 行权重` 除以当前未封顶行权重总和；
   - 用整数除法取得该行的基础分，余数保留为精确整数余数；
   - 余数更大的行优先取得尾分；
   - 余数相同的行按不可变、稳定的销售行 ID 升序决胜。
6. 逐行封顶：单行优惠不得超过该行可优惠金额，单行实付不得小于零。
7. 封顶后的再分配按以下方式执行：
   - 封顶行退出当前分摊集合；
   - 对剩余优惠分，在尚未封顶的适用行中按其原始权重重新归一化；
   - 按整数除法重新计算基础分和精确余数，再按余数降序、稳定 ID 升序分配尾分；
   - 若尾分分配使某行达到封顶，该行退出后，对仍未分完的优惠分重复以上过程；
   - 若可分配容量耗尽但优惠仍未分完，拒绝该次优惠计算，不得生成负优惠或负实付。
8. 优惠计算中，整单候选金额的舍入继续遵循 Spec 中现有、已确认的整单金额规则；将最终整单优惠统一到整数分后，再执行上述精确分摊。分摊算法自身不得使用中途小数舍入。
9. 验证所有适用行的行级优惠之和等于整单优惠，所有行实付之和等于整单应付。不得更改已经确认的促销资格或其他促销规则。

更新或新增验收场景，至少覆盖：

- 多个一分钱商品行分摊满减，不产生负优惠或负实付；
- 余数相同的行按稳定销售行 ID 升序分配尾分；
- 某行达到优惠封顶后，剩余优惠按未封顶行原权重重新分配；
- 行级优惠、整单优惠和实付金额总和守恒；
- 总优惠超过所有适用行容量时拒绝计算，且不生成部分销售记录；
- 不适用活动的行不参与分摊。

## 三、Q2：库存原单冲销的保守阻断规则

将“P1 无法精确追踪后续库存业务消耗自哪一笔收货”作为 P1 限制写入 Spec、PRD 和验收场景。本阶段不增加批次耗用或精确库存来源分配模型。

冲销任一已确认且产生库存流水的原业务单据时，按以下规则检查：

1. 逐条检查原单涉及的商品条码；对每个条码检查原单入账之后、同一条码在`在仓`和`在售`两个位置发生的全部库存变更。
2. 检查所有会改变库存的后续有效业务，包括销售出库、补货或位置转移、报损、库存调整及其他库存变更。后续新增的收货也计为后续有效库存变更。
3. 同一条码在任一库存位置存在后续有效库存变更时，拒绝冲销原单。不尝试判断后续变动是否实际消耗了原单数量，也不以净余额足够为由绕过阻断。
4. 其他条码的后续活动不影响该条码的冲销判断。
5. 按库存流水的持久化发生顺序判断先后，不按可回填的业务日期排序。若当前模型没有明确的流水顺序字段，则用系统生成的流水创建时间，并以稳定流水 ID 升序处理同一时刻的流水。
6. 后续业务只有在其原库存流水与配对反向流水均已完整冲销时，才作为一项完整撤销业务排除于有效后续活动之外。必须依据流水关联和完整冲销状态判断，不能只因净额为零就认定没有发生过后续业务。
7. 后续业务只完成部分冲销时，仍视为存在有效后续库存变更并阻止原单冲销。
8. 对原流水和反向流水按同一已撤销业务配对判断；完整冲销后不得将反向流水再次当成独立的有效后续业务。
9. 即使不存在后续有效库存变更，冲销仍须检查结果不会造成负库存。
10. 原单成功冲销时，保留冲销原因、原单关联和反向库存流水；同一原单不得重复冲销。

明确说明：该保守规则可能暂时阻止一些实际可逆的历史单据；P1 不通过估算或净额推断消耗来源。

更新或新增验收场景，至少覆盖：

- 同一条码在`在仓`或`在售`任一位置有后续有效库存变更时，冲销被拒绝；
- 同一条码后续有补货、销售、报损、调整或新增收货时，按保守规则拒绝；
- 不同条码的后续活动不阻止目标条码冲销；
- 后续业务及其配对反向流水已完整冲销时，按剩余有效流水重新判断；
- 后续业务仅部分冲销时，仍阻止原单冲销；
- 仅当没有后续有效变更且冲销不造成负库存时，允许冲销一次；
- 重复冲销不能生成第二组反向流水；
- 冲销被拒绝时，原单、库存和流水保持不变，并返回清楚原因。
