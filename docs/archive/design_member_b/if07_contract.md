## 1. 目的与范围

**来源**：交接包 §3 第 2 行（"尽早提出同次上下文、基线、S/W变动组、来源/转移关联、候选输出、拒绝语义及统一保存边界"）；交接包 §6；分工清单 IF-07"类型：业务内协作/只读核对"。

在同一工作副本内，按"商品＋位置（S=在售 / W=在仓）"核对本次完整数量变动、定位来源库存、生成待提交库存流水候选；或明确拒绝。**只产生候选，不保存**。

明确不做（**本文补充**：按分工清单"类型"与交接包 §6 的边界整理，未新增职责）：

| 不做 | 归属（来源） |
|---|---|
| 不保存、不写文件、不分配最终提交序号 | IF-05（交接包 §6；Spec §10.2） |
| 不做 D1 库存依赖/整单冲销判断 | IF-14（分工清单 IF-07"错误语义"） |
| 不做认证/权限 | IF-01（分工清单 IF-07 输入栏） |
| 不维护商品主数据/只读快照 | IF-06（分工清单 IF-07 输入栏） |
| 不判断售后资格、金额、期限 | IF-12（分工清单 IF-07 输出栏边界） |
| 不决定业务单据状态/审核结果 | 各业务包（分工清单"事务／保存边界"） |

## 2. 术语与库存模型

**来源**：Spec §7.1（位置表）；分工清单 IF-07"输入"（工作上下文/基线、位置 S 或 W、完整有符号变动清单）；ERD §6.2（余额由流水重建）。

- S/W 互斥、非负整数；T=S+W 只作派生展示，**不能用 T 绕过来源位置不足**（Spec §7.1、AC-13）。
- 变动组：一次业务确认涉及的**完整有符号数量变动集合**；示例（**本文补充**）：补货 W−q/S+q、销售 S−q、售后替换 S−q、报损（来源在仓 W−q 或来源在售 S−q）、期初/收货审核 W+q。
- 工作副本：IF-05（A 提供）创建的本次隔离副本；调用方持只读基线；本接口只在副本内读/校验/组装（分工清单 IF-07"事务／保存边界"）。
- 基线标识：建议 `baseLast = last_commit_ordinal`（D2，Spec §10.2）；具体载体待 A 的 IF-04/05 契约（**本文补充**：字段名为建议，不是已定契约）。

## 3. 输入（逻辑字段；DTO/类型/方法签名待评审）

**来源**：分工清单 IF-07"输入"栏原文："调用方本次工作上下文及其基线标识、条码/来源业务行/位置S或W、完整有符号变动清单、事件/转移/反向关联键；来源读取同一次工作副本，不由调用者传一个孤立余额当真"；交接包 §3 第 2 行六要素。

| 字段（**本文补充**：字段名为建议） | 必填 | 含义 / 来源 |
|---|---|---|
| `context` | 是 | 本次工作副本与基线标识；来自 IF-04/05（待 A 契约） |
| `request_key` | 是 | 本次业务请求键；幂等用（分工清单"幂等要求"） |
| `lines[]` | 是 | 本次完整变动组，至少一行 |
| `lines[].barcode` 或 `lines[].source_line_id` | 是 | 商品条码，或来源业务行（DOC_LINE.line_id）引用 |
| `lines[].position` | 是 | `S` 或 `W` |

| `lines[].source_ref` | 视场景 | 来源单/行：期初、收货审核通过（含 `receipt_review_id`）、补货/销售/售后业务行 |

## 5. 错误语义

> **v0.3 修订提示（2026-10-21）**：本节旧错误码（`SOURCE_INSUFFICIENT`/`INVALID_QUANTITY`/`DUPLICATE_EVENT`/`UNKNOWN_REFERENCE`/`OUT_OF_SCOPE`）为 v0.2 历史名；v0.3 起以共享规范 §4 稳定码与 §14.5 为准，代码按 §14 实现。保留原文仅作演进记录。

**来源**：分工清单 IF-07"错误语义"栏原文："位置不足、数量/引用不合法、补货双腿不配对/不守恒、工作副本过期、重复事件冲突；总余额不得弥补来源位置不足。D1作废依赖政策仍由IF-14判，不因普通查询扩大到所有同码事件"；Spec §13 R-INPUT。

| 错误（**本文补充**：错误码命名为建议） | 触发（原文） | 处理 |
|---|---|---|
| `SOURCE_INSUFFICIENT` | 来源位置不足 | 拒绝；总余额不得弥补来源不足 |
| `INVALID_QUANTITY` | 数量/引用不合法（R-INPUT 1–9999） | 拒绝且不写库 |
| `TRANSFER_UNBALANCED` | 补货双腿不配对/不守恒 | 拒绝 |
| `STALE_WORKING_COPY` | 工作副本过期 | 丢弃副本，用同一业务请求从最新状态重建（分工清单 §4.2） |
| `DUPLICATE_EVENT` | 重复事件冲突 | 拒绝或交 IF-05 判冲突 |
| `UNKNOWN_REFERENCE` | 商品/来源行/审核引用不存在 | 拒绝（**本文补充**：拆自"引用不合法"） |
| `OUT_OF_SCOPE` | 涉及 D1/权限/业务资格 | 转对应接口，不在此判定 |
| 保存类失败 | 校验/序列化/临时写/原子替换/恢复阻写 | 由 IF-05 返回（Spec §10.2；分工清单 IF-05） |

## 6. 保存与提交边界

**来源**：分工清单 IF-07"事务／保存边界"栏原文："在IF-05创建/管理的同次副本中读/校验/组装，由当前业务协调者顺序调用；不读写另一份全局可变余额，不自行保存。提交时IF-05再次对最新基线复核，任一行失败全单不生效；双腿同commit_ordinal"；交接包 §6；Spec §10.2。

- **不保存**、不写文件、不分配提交序号；候选交由业务协调者按序组装后，经 IF-05 **一次提交**。
- 只在同次副本内读/校验/组装；不读写另一份全局可变余额，不把可写共享 Map 交给多方并发修改。
- 提交时 IF-05 对最新基线复核；任一行失败**整单不生效**；同次全部流水同一 `commit_ordinal`（D2）。
- 失败/取消：只丢弃当前未提交副本，旧快照与 last 不变；重试从最新状态重算，不复用过期余额。

## 7. 幂等与防重

**来源**：分工清单 IF-07"幂等要求"栏原文："沿event_key、首次有效收货行、transfer_key/反向引用校验；提交重试不重复扣/加；同键异影响拒绝或交IF-05判冲突，不能生成新键绕过一次入账"。

- 沿 `event_key`、首次有效收货行（`receipt_review_id`＋`source_line_id`）、`transfer_key`、`reverse_of` 校验。
- 提交重试不重复扣/加；同键同内容由 IF-05 返回既有结果；同键异影响拒绝。
- 不得以换新键绕过一次入账（例如重试不得更换 `transfer_key`）。
- 一次业务确认的全部候选必须同次提交；部分提交视为错误（**本文补充**：由 §6 整单边界推出，不新增规则）。

## 8. 共享数据与读写边界

**来源**：分工清单 IF-07"共享数据"栏原文："STOCK_ENTRY/DOC_LINE来源与派生STOCK_VIEW；只暴露本次结果/只读状态，不把可写共享Map交给两个模块同时改"；ERD §4（STOCK_ENTRY 商品由 DOC_LINE.barcode 确定）、§6.2（余额=流水合计、缓存可重建）。

- 数据来源：`STOCK_ENTRY`、`DOC_LINE`、派生 `STOCK_VIEW`；收货审核通过引用 `RECEIPT_REVIEW`。
- 只暴露本次结果与只读视图；缓存只能由原/反向事实重建，**不得另改余额绕过流水**。
- 不新增实体/字段；不另存可漂移商品 FK。
- 双方不直接改对方内部实现；字段映射在类图 V1/V2 记录（分工清单"公共类型维护边界"）。

## 10. 请 A 确认的最小调用边界

**来源**：交接包 §6 原文"A只确认必要调用边界"；交接包 §9"A 需提供的输入"。以下 6 条为**本文整理**的确认项，不是新规则：

1. 期初（WP-01）与收货审核通过（WP-02）调用本接口时，W+q 的来源行/审核事件引用字段是否足够。
2. `baseLast`/单据 `version` 的实际载体，以及过期副本拒绝后的重建责任与顺序（IF-04/05 契约）。
3. 候选流水的组装者与 `commit_ordinal` 分配时点：确认由 IF-05 在提交时统一分配（D2），本接口不填。
4. 失败可见性与错误载体（业务拒绝/请求键冲突/过期副本/持久化失败）在 CUI 的呈现分工。
5. 商品只读快照（IF-06）调用时点：调用方先取商品再传条码，还是本接口内部取商品（建议前者，**本文建议**）。
6. 期初来源定位所需字段（期初来源单/行）在公共单据模型中的具体表达。

A 确认上述边界后，本契约视为稳定；后续随类图 V1/V2 受控修订，变更通知使用方适配（交接包 §3 第 2 行、§2.2）。

## 14. v0.3 修订：对齐共享规范 v1.02 §5.3（2026-10-21）

A 已发布《共享边界与接口规范》v1.02。本节为权威修订，覆盖本文件 §4/§8 中与规范冲突的表述；v0.2 其余内容作为历史来源保留。

1. **取消"来源可用量"语义**：删除 v0.2 §4 的 `source_locations`（"收货行→可用数量"）；IF-07 只返回商品/位置余额，不按收货单计算剩余可用量，也不追踪耗用来自哪次收货。`sourceLineId`/`receiptReviewId` 仅用于流水业务来源、防重/核对。
2. **签名（以规范 §5.3 为准）**：
   - `balances(wc: WorkingCopy, overlay: OverlayView, barcodes: List<String>) -> ReadResult<List<StockBalance>>`
   - `check(wc: WorkingCopy, overlay: OverlayView, changes: List<StockChangeLine>) -> CandidateResult<StockCheckResult>`
   - `wc` 由 IF-04 `open(op)` 取得；`overlay` 为调用前已合并的只读候选视图；`check` 的 `changes` 是尚未并入 overlay 的完整变动组。
3. **overlay 合并规则**：子服务只返回本次新增候选，不返回累计 overlay；业务协调者每次成功调用后合并一次；重复调用同一组不得再次叠加，按 eventKey/稳定键识别；调用失败不合并。
4. **结果分类**：`balances` 用 `ReadResult`（VALUE/REJECTED/FAILED）；`check` 用 `CandidateResult`（PREPARED/REJECTED/FAILED）；PREPARED 不是业务成功、不分配 commitOrdinal。
5. **错误码**：沿用规范 §4 稳定码（`INSUFFICIENT_STOCK` 带 barcode/position/available/requested、`TRANSFER_UNBALANCED`、`EVENT_CONFLICT`、`STALE_WORKING_COPY`、`REFERENCE_INVALID` 等）；本接口不新增业务细分码，确需时由 B 通知调用方。B 骨架另登记一个 FAILED 业务码 `STOCK_CHECK_FAILED`（内部/依赖读取异常），需通知 A 记录。
6. **不保存、不嵌套提交**：仍由业务协调者持唯一 `ChangeSetBuilder`，经 IF-05 一次提交；`CustomerReturnLossRecorder` 作为售后子调用时只能组装候选，不得调用 submit/execute 模板入口。
7. **权限**：由业务入口与 IF-05 复核；本接口不代替 IF-01 身份校验，不接受裸 `operatorId` 作为授权。
8. **待 A 实现/确认**：A 的 `WorkingCopy`/`OverlayView`/`ReadResult`/`CandidateResult` 公共类型交付前，本契约用同名逻辑类型描述；B 以替身实现/自测，不复制 A 公共类型。

影响：v0.2 §4 的 `source_locations` 与 §8 中"来源定位"表述不再有效；其余输入/输出/幂等/共享数据边界按本节调整。v0.3 不改变业务规则，只对齐调用契约。
