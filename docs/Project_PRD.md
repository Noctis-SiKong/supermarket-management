## 2 产品概述与目标

为单家实体超市的管理员、店长和店员提供PC Java CUI本地业务：实际收货审核、两位置数量库存、销售付款确认、单活动择优、顾客退换及损耗/作废追溯。目标是让库存、原成交实付及售后结果可核对，同时保留课程真实设计/HAI证据。以轻量、好用、刚需组织既有需求，不新增商城/连锁或生产指标。

单机单进程、核心离线、Maven/JDK17/JUnit4.13.2、Jackson UTF-8 JSON/schemaVersion、BigDecimal/RMB、Asia/Shanghai均为当前基线；课程规定Java/CUI、集合、File I/O和标准构建，具体库/版本是用户选择，不冒称课程指定。首次获取构建依赖与业务离线运行分开验证。未来只保留扫码/硬件接口，不连接专用设备，不做支付网关或挂单。

### PRD-06 整单单活动促销

对应Spec FR-06、BR-09/11/28、§7.3、ERD-C01/02；E。每候选只用一个活动，非适用品原价，按落分后的整单应付择最低；同价按既有显式优先级及活动ID决胜，不叠加。满减门槛为活动适用销售行折扣前金额合计。选中方案后，满减优惠仅分摊给符合条件行：权重=该行折扣前金额÷适用行折扣前金额合计；分摊金额按两位HALF_UP落分，稳定销售行ID升序的最后一个符合条件行承接优惠总额与前行分摊合计的尾差。非活动行折扣为0、实付为原行金额。折扣活动保存折扣后的行实付及行优惠；行优惠=折扣前行金额−行实付；行实付合计必须等于选中方案的订单应付。销售确认保存商品名称、单价、数量、促销快照、分摊折扣、实付及稳定行ID，之后不随商品/活动修改。

追踪：Q07/M-ROUND/R-PROMO；AC-16/32/41/44/54/55。

### PRD-07 原销售退货及部分退款

对应Spec FR-07、BR-12/13/14/21/26/29、§7.4及ERD-C03–09；E。店员关联原销售、核验既有30天与资格规则，读取原行实付及双剩余额度→按P×q/Q两位HALF_UP并封顶、最后结清用剩余金额→原子记录退款/核销/损耗去向。每条原销售行独立维护售后核销台账。设原购买数量Q、原行实付P；有效已退数量Qr/金额Mr、已换数量Qx/原商品抵扣金额Mx；剩余数量=Q−Qr−Qx，剩余金额=P−Mr−Mx。必须同时满足0≤Qr+Qx≤Q、0≤Mr+Mx≤P。换货先占用原销售行数量和实付金额，后续退货只能使用剩余额度；已生效核销不能被后续换货覆盖。部分退/换数量q必须为正且≤剩余数量；未结清时本次占用金额=min(HALF_UP(P×q÷Q,2),剩余金额)，最后一次结清剩余数量时占用全部剩余金额。退款直接使用原销售行保存的实付，不跨行重新分摊退款预算、不按原价或当前活动重算。换货占用的是原商品抵扣额度，不是新品售价或实际补退差；同款同数量质量换零补差也必须核销原数量及对应实付额度。每次核销记录原销售行、来源退/换单及明细、数量、金额、类型、经办人、时间、幂等标识及状态；同一请求重复提交不再次占用。退款、核销及替换品在售扣减按既有原子/防重规则同步，失败不留下部分生效。合法授权冲销以关联反向记录释放原数量/金额，保留原记录及原因，不物理删除、不重复释放。

追踪：Q08/R-REFUND/R-AFTERSALE-LEDGER；AC-09/15/17/33/46/54/56–59。

## 6 主要业务流程与数量影响

1. 收货登记待审，不计两位置；店长审核通过一次入在仓，无图仍可审；不录商品日期或选批次。
2. 补货在仓−q/在售+q，总量不变，只按商品及位置数量校验；不足拒绝。
3. 销售选商品/数量→同品同价合并→候选单活动择优→按适用行原额比例分摊并保存优惠/实付快照→确认收款和在售扣减整单原子生效。
4. 退货关联原行→核验期限/资格和共享剩余数量/金额→按原行P×q/Q及尾款规则退款→保存核销及损耗去向；交回不回库。
5. 换货关联原行→先占用数量/实付额度→计算新品与抵扣的补退差（同款同数量质量换0差仍占额度）→扣替换品在售→记交回去向；后续退款只用剩余额度。
6. 报损及授权作废沿用既定权限；冲销关联原核销记录并反向释放数量/金额，保留历史，幂等且不负库存。查询权限不变。

P1、P2均无商品日期、批次、过期处理步骤。经办时间、促销有效期和30天售后期限保留。
