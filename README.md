## 范围与技术边界

P1为Java CUI，采用集合与文件持久化；已选Maven、JDK 17、UTF-8 JSON/Jackson。P2才扩展GUI和Derby；课程允许的GUI选型以Spec为准。ERD表达逻辑关系，不表示P1必须使用关系数据库。

已确认范围以Spec为准，包括收货审核、在售/在仓库存、补货、销售促销、按原销售行实付办理退换、数量及金额双额度核销和审计。当前基线从P1、P2均移除了商品日期、临期/过期、批次及过期拦截；不因发布到GitHub重新扩展范围。

## 路径基准与维护规则

以下定义仅适用于本仓库。**仓库根目录是包含`README.md`、`.gitignore`和`docs/`的顶层目录；clone后不再套一层`Project1`。**所有文档中的代码样式路径均为仓库相对路径；不记录或管理仓库外目录。

| 名称 | 逻辑定义与归属 |
|---|---|
| 仓库根目录 | 仓库顶层；本机checkout名为`Project1`，README、.gitignore、docs直接位于此处 |
| 仓库文档目录 | **仓库相对路径**`docs/`；共同维护的Spec/PRD/ERD主副本，可含中文，不是仅英文文件目录 |
| Markdown相对链接 | 只相对于该Markdown文件所在目录解析；代码样式的仓库相对路径不是同一种链接 |
| 运行数据根目录 | `DATA_ROOT`=仓库根目录下`data/`；根解析/可写性/子布局待设计，不等于Markdown目录 |

### 文档主副本

仓库`docs/`是Spec/PRD/ERD的唯一协作主副本；不再维护仓库外副本，也不在文档中记录外部归档或备份位置。修改需求/设计时直接在仓库内评审，历史版本由Git记录。

### 计划路径与报告安排

文档中代码样式的`docs/evidence/...`、`docs/design/...`、`docs/decisions.md`或`docs/decisions/...`均为**仓库相对路径**。现在存在的是Spec/PRD/ERD/分工清单四个文档及`docs/erd/`四个图源；`docs/evidence/`、`docs/design/`、`docs/decisions/`和`docs/decisions.md`均为计划位置，尚未创建。不为了让计划“看起来完成”而创建空证据文件；也不新建重复路径治理记录。

工作阶段以仓库`docs/`的中文Spec/PRD/ERD为协作主副本；提交前将最终报告转为英文，并从提交包/最终交付目录移除中文工作稿，中文稿不作为并行最终报告。中文工作稿不是提交报告，不设正式§2.6/§3.7声明；正式声明只在英文最终报告中由本人按模板要求完成并签署，中文工作稿不替代声明。英文最终报告使用仓库根目录下的英文报告存放位置；最终文件名在报告装配时确定，本轮不新增报告子目录或改变Canvas安排；仓库根目录可包含中英文工作文档、代码和构建文件。

文档历史由Git记录，本文档不定义仓库外备份位置。运行数据上一版JSON快照、临时写文件及附件恢复副本属于运行时存储，使用`DATA_ROOT`内的待定布局，**不得复制进仓库**。提交课程作业的ZIP/报告/演示证据不是运行数据，不用全局日志或压缩包通配符忽略它们。

### 运行数据与附件：已知契约和未决设计

已确认的是UTF-8 JSON单快照/schemaVersion、原子替换/上版恢复和附件相对路径＋哈希；`DATA_ROOT`已定为仓库根目录下`data/`，根解析/可写性/子布局及启动失败体验仍待设计。详见[Spec运行路径设计待确认项](./docs/Project_Spec.md#101-运行路径契约与待确认设计)；不把剩余技术方案当作已批准部署规则，也不增加课程手工配置门槛。

旧文中的`data/`仅指运行数据逻辑根`DATA_ROOT`，旧`data/attachments/`统一表达为`DATA_ROOT/attachments/`；附件记录内只保存`attachments/<文件名>`，**相对于DATA_ROOT而非工作目录、JAR、仓库或Markdown目录**。根位置已定为仓库根`data/`；本轮澄清相对基准，不创建数据目录/运行文件，子布局仍待设计。

路径安全契约：落盘的附件`relative_path`统一用`/`；拒绝盘符/UNC/根路径等绝对引用、URI、空路径、反斜杠、`.`/`..`段及解析后越出DATA_ROOT的引用。将根与目标规范化并校验最终真实位置（包括符号链接/联接点），以路径组成部分判断包含关系，不能用字符串前缀冒充。写入前及实际打开时均核查，避免链接把目标引到根外。CUI选择待导入源图片可使用用户本机路径，但**源绝对路径不得序列化成附件引用或写入Git材料**。

中文和空格是合法文件名字符，不用按空格分词或拼接Shell命令操作文件；目标生成名/重名策略尚待确认，不能默默覆盖现有文件或把源目录/用户名编码进目标名。复制/读取/校验失败不得保存“附件成功”引用，不覆盖已验证副本；没有附件时仍按既有规则允许审核，不因路径治理新增强制上传。对既有引用缺文件或哈希不符，不把它当作正常附件、不偷偷移除历史关联；是否阻断相关操作、如何提示/修复与附件孤立副本清理属于待审设计，不能擅改收货审核或业务恢复规则。附件单张上限已按`5,000,000`字节同步；一般失败/重名/碰撞策略仍待设计。
